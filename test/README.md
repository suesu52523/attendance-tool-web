# 测试说明

本工具是纯静态页面，无需构建。测试用 Node 直接加载 `js/main.js`（源码包进 `new Function`）并注入
`XLSX` / `document` / `Blob` / `URL` 桩，只测逻辑，不依赖浏览器；导出函数用"捕获桩"记录生成了哪些
sheet，因此可以断言"没有数据时不会导出示例数据"这类行为。

## 1. 单元测试（零依赖）

```bash
node test/main.test.js
```

84 项，覆盖历次修复的问题：

- **日期时间归一化**：`padTime`（Excel 的 `8:15` 对齐文本 `08:15`）、`parseTimeParts` 拦截 `25:70` / `24:00`、
  `toYYYYMMDD` 整串匹配（不再把 `2026/8/10x` 截成合法日期）
- **合并大表定位 `locateMergedRecords`**：工号 + 日期（+ 开始时间），时间兼容 `7:00 / 07:00 / 15:45:00`，
  时间对不上返回空而不是降级为同日候选
- **异常表匹配 `processAbnormalWorkbook`**：姓名不参与定位（多一个字 / 留空都仍能匹配，只给提醒）、
  0 条进失败清单、同人同日多条标 `多条命中(n)`
- **整改表解析 `processRectifyWorkbook`**：保留 `原开始日期 / 原开始时间` 定位键、空处置方式标 `未填写`
- **批量操作定位 `applyBatchOperations`**：只用业务键（工号 + 原开始日期 + 原开始时间，**序号不作身份**）、
  未定位与多条命中都不改数据并记入清单、空合并大表时 `applied = 0`、
  **无法识别的处置方式（"删除加班""已改"等自由文本）进「未识别」清单，不再静默忽略**
- **`confirmBatch`**：执行后写 `locateIssues`、**不能重复执行**（防止按重排后的序号删错人）、
  存在 `未填写` 时整轮阻断
- **导入校验**：整行空白跳过（不计失败）、时间越界进失败清单、
  **重复填报检测（同一工号同一天同一开始时间出现多次 → 导入页提示 + 可下载清单）**
- **页面渲染**：未导入班组表时提示先完成导入、未导入文件时标注「示例数据」、定位异常在整改页与输出页可见
- **导出保护**：没数据时导出汇总 / 整改表不生成任何文件
- **M3 导入补强（2026-09-18）**：加班时数必须是「数字 / >0 / ≤48」（`半小时`、`0`、`-3` 都退回；
  文本形式的 `"2.5"` 仍放行）、整改表 `修改后时数` 不合理时不执行并进定位异常清单、
  **班组表列名被改（缺列 / 多列）会提示**（不再静默丢那一列）、
  **《匹配失败记录》多一列「线索」**（同一天大表里的记录 + 工时是否一致；当天没有则指向最近一次）

## 2. 场景测试（用「测试数据」文件夹的真实数据生成的文件）

数据来自 `test/_data_testcases.json`（由主项目的 `python test/dump-test-data.py` 从
`shuju/测试数据/*.xlsx` 导出，浏览器里 SheetJS 的解析结果等价于此 JSON）。

```bash
node test/scenarios.test.js
```

14 项，覆盖 6 个场景：

| 场景 | 文件 | 断言要点 |
|---|---|---|
| 1 | `01-班组填报-正常.xlsx` | 17 个 sheet、241 条、0 校验失败 |
| 2 | `02-班组填报-校验失败.xlsx` | 30 行 → 失败 17 / 合并 11；完全空行不再计失败；`25:70`、`24:00` 被拦 |
| 3 | `07-异常表-可匹配.xlsx` | 60 条 → 已匹配 54 / 未匹配 6 / 需人工核对 4；姓名不一致只提醒不判失败；整改表只含 54 条 |
| 4 | `12-整改表-真实自由文本.xlsx` | 42 条操作（6 可识别 / 36 条自由文本进「未识别」清单）；**删除/调班/修改都按业务键命中整改表里写的那个人**，不再按 ID 撞上别人 |
| 5 | `13-整改表-定位异常.xlsx` | 24 条（源文件尾部空行不计）→ 13 条按业务键定位、1 条未填写、10 条进定位异常清单（未定位 7 + 多条命中 3）；未定位与多条命中都不改数据 |
| 6 | 01 + 07 + 12 | 全流程连通：确认执行 → 输出页 / 汇总 / 调班 / 操作记录 / 定位异常清单导出均正常 |

## 4. 回归时请重点看这几条

改动 `js/main.js` 后，只要下面两条还 PASS，就说明"改错行"这一类问题没有回来：

- `test/main.test.js` → `ID 撞上别人时不删错人，按业务键定位到正确记录`
- `test/scenarios.test.js` → `删除 / 修改 都按业务键定位到整改表里写的那个人（不再按 ID 撞上别人）`
- `test/scenarios.test.js` → `24 条操作…`（尾部空行不再算数据；空行会让整改表被判“未填写”而假阻断整轮）
- `test/main.test.js` → `匹配失败给出线索…` / `加班时数填成文字「半小时」被退回…`（M3 补强后的行为）

> 注意：`index.html` 里引用的是 `js/main.js?v=YYYYMMDD-N`，改完 `main.js` 记得把版本号 +1，
> 否则浏览器会用缓存里的旧脚本。
